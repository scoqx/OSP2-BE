# Управление и расширенные возможности OSP2-BE на сервере Quake 3

## Отключение BE-функций

### Основной переключатель: be_enabled

Все BE-функции можно полностью отключить, установив `be_enabled 0` на клиенте. Это отключит все расширенные возможности OSP2-BE.

```c
// Полностью отключить все BE-функции
seta be_enabled "0"
```

### Серверное управление функциями (CS 888)

Сервер может выборочно отключать определённые BE-функции через configstring **888** (`CS_OSP2BE_DISABLED_FEATURES`). Значение — сумма битовых масок отключаемых функций.

| Битовая маска | Функция           | Описание                                                      |
|---------------|-------------------|---------------------------------------------------------------|
| 1             | Team wh           | Wallhack союзников, global pos (бит 4 `cg_friendsWallhack`)   |
| 2             | Model sound       | Выбор звуков моделей                                          |
| 4             | Alt grenades      | Альтернативные гранаты                                        |
| 8             | Enemy lightning   | Цвет молнии противника                                        |
| 16            | Mark teammate     | Маркировка союзников                                          |
| 32            | Alt shadow        | Альтернативная тень                                           |
| 64            | Alt blood         | Альтернативная кровь                                          |
| 128           | Alt plasmagun     | Альтернативная плазма                                         |
| 256           | Outline           | Контуры игроков                                               |
| 512           | Team indicator    | Индикатор команды                                             |
| 1024          | Damage info       | Информация о нанесённом уроне                                 |
| 2048          | Fullbright        | Полная яркость моделей/оружия                                 |
| 4096          | Team tasks        | Командные задачи                                              |
| 8192          | No explosions     | Отключение взрывов                                            |
| 16384         | Team frozen       | Wallhack замороженных союзников                               |
| 32768         | HUD markers       | Маркеры на HUD (игроки)                                       |
| 65536         | Replace steps     | Убрать звук шагов по метал. поверхн.                          |
| 131072        | Autojump          | Автоматический прыжок                                         |
| 262144        | Hitbox            | Запретить отображение хитбокса                                |

```c
// Отключить damage info (1024) и fullbright (2048)
set cs 888 "3072"

// Отключить все функции
set cs 888 "524287"
```

Игроки проверяют доступность через `/allowedfeatures`.

## Функции, требующие серверной поддержки

### cg_damagePlums (плавающие числа урона)

- **Серверный cvar:** `g_damagePlums`
- **Клиентский cvar:** `cg_damagePlums`
- **Фильтр по оружию:** `cg_damagePlumsWeapons` (битовая маска: 1 gauntlet, 2 MG, 4 SG, 8 GL, 16 RL, 32 LG, 64 RG, 128 PG, 256 BFG)

### cg_autohop (автоматический прыжок)

- **Серверный cvar:** `pmove_autohop`

```c
set pmove_autohop "0"   // отключено
set pmove_autohop "1"   // включено, игроки не могут отключить
set pmove_autohop "2"   // включено, игроки могут управлять
```

### CS 889 — турнирные ограничения

**Configstring:** `CS_OSP2BE_TOURNEY_RESTRICTIONS` (889). Целое число — битовая маска.

| Бит | Значение | Описание                                                  |
|-----|----------|-----------------------------------------------------------|
| 1   | FPS lock | `com_maxfps` принудительно 125 или 250 на время матча     |

```c
set cs 889 "1"
```

### CS 890–909 — каталог предметов / спавнов / телепортов

**Configstrings:** `CS_OSP2BE_ITEM_CATALOG0` … `CS_OSP2BE_ITEM_CATALOG_LAST` (890–909). Клиент склеивает все 20 строк в один payload (до ~20 KiB). BE-only — обычный `/configstrings` их **не показывает** (как 888/889); смотри лог сервера `Item catalog: mode=…` или `/testq3lb`.

Единый каталог обслуживает:

| Клиент / элемент HUD                              | Режим   | Назначение                                        |
|---------------------------------------------------|---------|---------------------------------------------------|
| `cg_shadowItems`                                  | бит 1   | Призраки 3D-пикапов на месте респавна             |
| SuperHUD `Spectator_ItemSpawns*`, `ItemPickups*`  | бит 2   | Таймеры и уведомления о подборе (зрители)         |
| `cg_drawSpawns` / world flags                     | бит 4   | Точки респауна (если нет локального QSP1)         |
| `cg_drawTPexit`                                   | бит 8   | Выходы телепортов (если нет локального QTX1)      |

Если сервер не задаёт каталог (или режим не включает нужный бит), клиент для `cg_shadowItems` использует **QITM** из mapdata; для спавнов/теле — QSP1/QTX1.

**Spawn segment:** `sp;<x>,<y>,<z>,<yaw>,<sf>,<count>,<role>,<team>`  
**TP exit segment:** `tde;<x>,<y>,<z>,<yaw>`  
Координаты — origin × 10. Role/team как в QSP1 (0..6 / 0..3).

#### Как собрать каталог для PUI

**mode** для чистого PUI — **`2`**. Если нужны и shadow items — **`3`**. Спавны/теле добавляют биты **4** / **8** (например всё сразу — mode **`f`** = 15).

##### Какие предметы попадают в trackId

Только эти abbrev (остальные в каталог можно добавить для shadow, но trackId и `pui` их не касаются):

| abbrev | Предмет        | abbrev | Предмет      |
|--------|----------------|--------|--------------|
| `mh`   | Mega Health    | `qd`   | Quad Damage  |
| `ra`   | Red Armor      | `bs`   | Battle Suit  |
| `ya`   | Yellow Armor   | `reg`  | Regeneration |
|        |                | `inv`  | Invisibility |
|        |                | `hst`  | Haste        |
|        |                | `flg`  | Flight       |

##### Алгоритм сборки

1. Обойти пикапы **слева направо** в том порядке, как они должны идти в SuperHUD.
2. Для каждой **физической точки** на карте — один **segment**:
   - один предмет: `mh;1280,960,320`
   - team pad (RA+YA): `ra/ya;640,1280,64,1` — abbrev через `/`, **одна** тройка координат
3. Координаты — **origin × 10** (деци-единицы). Пример: `(128, 96, 32)` → `1280,960,320`.
4. В **CTF** для каждого PUI-segment добавить **`,side`**: `0` нейтральный, `1` red, `2` blue.
5. Сегменты склеить через **`|`**; в начало payload поставить **mode**.
6. Разбить строку по CS 890–909 как удобно — клиент склеит обратно.

##### Пример: карта с mega, red RA/YA pad, нейтральный quad

Порядок в HUD: mega → RA → YA → quad.

```
2mh;1280,960,320|ra/ya;640,1280,64,1|qd;5120,3840,160
```

| trackId | segment              | abbrev | side |
|---------|----------------------|--------|------|
| 0       | `mh;1280,960,320`    | mega   | —    |
| 1       | `ra/ya;640,1280,64,1`| RA     | red  |
| 2       | `ra/ya;640,1280,64,1`| YA     | red  |
| 3       | `qd;5120,3840,160`   | quad   | —    |

```c
set cs 890 "2mh;1280,960,320|ra/ya;640,1280,64,1|qd;5120,3840,160"
```

Эти trackId (`0…3`) — те же числа, что **`pickId`** / **`nextId`** в команде `pui` (см. ниже).

##### Частые ошибки

| Ошибка | Что будет |
|--------|-----------|
| `mode=1` | PUI не работает — клиент игнорирует каталог для спектаторского HUD |
| `rl;…` в каталоге без PUI-abbrev | В shadow виден, trackId не выдаётся, `pui` по нему не шлётся |
| RA и YA разными segment | Два pad вместо одного — таймеры и `nextId` не сработают как team pad |
| Забыли `,side` в CTF | Клиент отбросит segment |
| Координаты без ×10 | Призраки/таймеры смещены |

#### Формат payload (справочник)

```
<mode><segment>|<segment>|...
```

- **mode** — один hex-символ `0-9a-f` (битмаска & 15):
  - `1` — shadow catalog
  - `2` — PUI (спектаторский HUD)
  - `4` — spawns (`sp;…`)
  - `8` — tp exits (`tde;…`)
  - можно комбинировать (например `3` = shadow+PUI, `f` = всё = 15)
- **segment** — item/PUI слот:

```
<abbrev>[/<abbrev>...];<x>,<y>,<z>[,<side>]
```

или spawn / tp exit:

```
sp;<x>,<y>,<z>,<yaw>,<sf>,<count>,<role>,<team>
tde;<x>,<y>,<z>,<yaw>
```

| Поле     | Описание                                                                                      |
|----------|-----------------------------------------------------------------------------------------------|
| `abbrev` | Короткое имя предмета (`mh`, `ra`, `ya`, `qd`, …). Полный список — таблица в `cg_shadowitems.c`. |
| `/`      | Альтернативы одного слота (team pad: RA/YA и т.п.).                                           |
| `x,y,z`  | Координаты в **деци-единицах** (origin × 10).                                                 |
| `side`   | `0` нейтральный, `1` red, `2` blue. В CTF для PUI-сегментов сервер обязан передавать; вне CTF можно опустить (все `0`). Shadow-only сегменты side не используют. |

Полный список abbrev для shadow catalog — `cg_shadowitems.c`. Разбиение по CS 890–909 произвольное.

### Servercmd `locs` — origins локаций

Если клиент в `beinfo[6]` выставил бит **16** (`BE_MAPDATA_NEED_LOCS` — нет локального QLM1), сервер шлёт:

```
locs <id> <x10> <y10> <z10> <id> <x10> <y10> <z10> ...
```

`id` совпадает с индексами `CS_LOCATIONS`. Имена уже в configstrings. Несколько команд, если не влезает в ~900 байт.

#### Команда `pui` при подборе

Когда в каталоге включён режим PUI (бит 2), сервер при подборе отслеживаемого предмета шлёт **только зрителям** (`TEAM_SPECTATOR`), не broadcast `-1`.

```
pui <cmd> <readyTime>
```

##### Шаг 1 — trackId из каталога

Нумерация **слева направо** по всем PUI-abbrev в payload (`mh`, `ra`, `ya`, `qd`, `bs`, `reg`, `inv`, `hst`, `flg`). Оружие и прочие abbrev в trackId не входят.

Для примера каталога из раздела выше (`2mh;…|ra/ya;…|qd;…`):

| trackId | Сегмент           | Предмет |
|---------|-------------------|---------|
| 0       | `mh;1280,960,320` | mega    |
| 1       | `ra/ya;…,1`       | RA      |
| 2       | `ra/ya;…,1`       | YA      |
| 3       | `qd;0,0,512`      | quad    |

На team pad `ra/ya` два trackId подряд: подобрали RA → `pickId=1`, `nextId=2`; подобрали YA → `pickId=2`, `nextId=64` (следующего на pad нет).

##### Шаг 2 — упаковать cmd

```
cmd = picker * 1048576 + pickId * 1024 + nextId
```

| Поле        | Откуда взять                                                                 |
|-------------|------------------------------------------------------------------------------|
| `picker`    | clientNum подобравшего игрока (`0…63`)                                       |
| `pickId`    | trackId подобранного предмета                                                |
| `nextId`    | trackId следующего предмета **на том же pad**, или **64** если его нет       |
| `readyTime` | `level.time + respawn_ms` — момент респавна в serverTime; **0** сброс таймера |

##### Шаг 3 — примеры

Игрок **client 2** подобрал **RA** (track 1), YA на pad respawn через 25 с, `level.time = 120000`, respawn 25000:

```
picker  = 2
pickId  = 1
nextId  = 2
cmd     = 2*1048576 + 1*1024 + 2 = 2098178
readyTime = 120000 + 25000 = 145000

pui 2098178 145000
```

Тот же игрок подобрал **mega** (track 0), один предмет на слоте, respawn 35 с:

```
picker  = 2
pickId  = 0
nextId  = 64
cmd     = 2*1048576 + 0*1024 + 64 = 2097216
readyTime = level.time + 35000

pui 2097216 155000
```

##### Шаг 4 — кому слать

Перебрать клиентов в `TEAM_SPECTATOR` и каждому:

```c
trap_SendServerCommand(spectatorClientNum, "pui %d %d", cmd, readyTime);
```

Игрокам в red/blue/follow команду **не** отправлять — клиент обрабатывает `pui` только в режиме зрителя.

> **Metarena:** мод сам строит каталог (CS 890–899) и шлёт `pui` при подборе. Ручная сборка нужна только своему серверному mod-коду.

Категории призраков для shadow items задаются клиентским **`cg_shadowItems`** (битовая маска: health, armor, weapon, ammo, powerup, flag).

## Функции с опциональной серверной логикой

### cg_respawnWeapon (оружие при респауне)

Клиент выбирает оружие через `cg_respawnWeapon` (`0` — по умолчанию, `1`…`8` — gauntlet…plasmagun). Для корректной работы сервер должен учитывать настройку клиента при выдаче оружия на респауне; иначе игрок сначала получит серверное оружие по умолчанию, затем переключится на выбранное.

```c
seta cg_respawnWeapon "7"   // рейлган
seta cg_respawnWeapon "0"   // оружие сервера
```
